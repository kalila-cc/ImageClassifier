# 媒体支持

## 格式与降级行为

| 媒体 | 支持行为 | 验证重点 |
| --- | --- | --- |
| JPEG、PNG | 缩略图、预览、移动、裁剪、旋转 | EXIF 方向、透明通道、色彩与大尺寸 |
| HEIC/HEIF | iPhone 静态图及 Live 静态部分解码 | 随安装包部署的解码器、真实导出文件 |
| iPhone Live Photos | 静态展示、动态预览、关联成员整体操作 | 配对标识、成员缺失、重名和中断 |
| MP4、MOV 视频 | 缩略图、时长、播放、进度跳转、原文件移动 | 容器内实际编码、方向、声音和播放兼容性 |

文件扩展名不代表编解码兼容性。不能预览的素材保留占位卡片、类型、错误和外部打开入口；仍允许明确识别的独立文件移动，不自动删除。未明确支持的其他格式在扫描结果中列出。

## Live Photos 配对

一个 Live Photo 是一个媒体资产，可对应静态照片和配套视频两个物理文件。网格展示一张带 Live 标记的卡片，计一个批次名额；静态预览使用照片，播放使用关联视频。已配对的视频不再作为普通视频重复入队。

优先使用导出文件中的配对标识识别关系。同名照片与 MOV 只构成候选，不能直接视为已配对。歧义时提供确认、手动配对或拆分；成员缺失时显示不完整，未经明确选择不把可能关联的文件静默拆开移动。扫描配对元数据不依赖全库视觉分析。

移动、改名、归档和撤销以完整资产为单位，保留成员内容及配对元数据。重名时为成员统一规划名称，所有成员成功才报告整个素材成功。未知伴随文件不自动删除，只有确认的成员参与整体操作。

从 Live 静态部分裁剪时，导出普通静态子图，原照片和配套视频一起归档。裁剪与归档规则见[图片编辑](04-editing.md)，多文件中断处理见[文件安全](06-file-safety.md)。

## 视频与资源使用

视频归类保持原文件，不转码、不剪辑。网格只显示静态缩略图；用户主动播放时启动一个播放器，切换素材释放上一播放器资源，避免同时自动播放大量视频或 Live 图。

边界检查可使用视频代表帧与时间作为辅助，不能以单帧推断整段视频内容。代表帧获取失败时进入不确定判断，不将视频全片解码分析。

Qt Multimedia 负责播放，图片解码单独处理。视频 HEVC 可播放不意味着静态 HEIC 一定可读；两者独立验证并随安装包交付必要组件。

## 实现参考

- [Apple pairedVideo](https://developer.apple.com/documentation/photos/phassetresourcetype/pairedvideo)：Live Photo 配套视频资源定义。
- [Qt QImageReader](https://doc.qt.io/qt-6/qimagereader.html)：图片尺寸、方向与解码接口。
- [Qt Multimedia](https://doc.qt.io/qt-6/qtmultimedia-index.html)：播放与视频帧接口，实际编码支持需在部署环境验证。
