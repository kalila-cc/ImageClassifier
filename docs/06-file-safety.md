# 文件安全与恢复

## 操作约束

所有真实文件变更先记录意图，再执行，最后核对并提交结果。SQLite 与文件系统不能组成同一个原子事务。内部进度为已计划、执行中、目标已落盘、来源清理完成、已提交；失败保留可恢复记录。

执行前复核来源身份和版本，锁定同一资产及冲突目录子树。目标名称在实际创建时防冲突，不能只依赖提前检查不存在。文件重名保留原内容并为新文件分配名称，目录重名不自动合并。

## 移动与写入

| 操作 | 执行规则 |
| --- | --- |
| 同盘移动 | 优先重命名；核对成功后更新路径与操作记录 |
| 跨盘移动 | 写目标临时文件、校验完整性并确认来源未变、提交目标，再核对正式目标的大小与 SHA-256，最后删除来源 |
| 原文件复制 | 写临时文件、核对来源与目标内容、提交后再次校验；来源始终保留 |
| 裁剪导出 | 在目标旁临时写入并记录 SHA-256，提交正式名称后再次校验，成功才记为完成；重试核对已有结果 |
| Live 跨盘移动 | 所有成员先复制并校验，确认全部目标后再清理来源 |
| Live 同盘移动 | 逐成员操作；部分失败时安全回退或进入恢复，不能报告整项成功 |
| 跨盘目录移动 | 逐项记录并保留子树，所有成员成功后清理旧目录 |
| 目录改名或移动 | 协调子树内其他操作，成功后更新索引、草稿目标和资产定位 |

跨盘内容使用校验和验证复制完整性。目录移动影响全部内容，包括不在媒体索引中的文件；操作前展示范围，禁止移入自身或后代。未知成员及操作过程中新增文件必须核对，不能被递归清理误删。

正式目标在校验与来源清理期间持有只读保护句柄，拒绝其他进程写入、删除或重命名。正式目标与记录不符时，跨盘移动保留来源，裁剪输出不记为成功；恢复清理也在目标保护期间执行。

取消只停止未开始部分，已完成项仍有效；撤销是另一个命令。批量结果逐文件记录，再汇总到媒体资产。磁盘空间不足、占用、断连与权限错误分别报告，不阻塞无关项。

## 裁剪与文件操作协调

每个裁剪请求的最新成功输出经校验后在重试中复用；系统明确确认该输出已不存在时，以新操作编号重新生成，保留原有历史。无法读取不视为删除，内容不符与未完成记录分别拦截并提示。多子图重试仅重新生成缺失项，回收原图时关联和校验各子图实际使用的输出编号。所有子图保存在原图目录并加入当前列表；仅裁剪保留原图，多子图的裁剪并删除原图在全部输出核对后回收原件。学习记录写入失败单独提示，不撤回成功输出。后续通过独立移动或复制进行归类。

单子图原位覆盖使用 `replace_image` 操作及 `image_replacements` 保存原始哈希、临时输出与备份位置。临时结果以原格式写入、成功解码并计算哈希，锁定并核对原图版本后使用 `ReplaceFileW` 替换，保留旧原件备份。核对新文件及旧备份哈希后，在同一数据库事务中提交覆盖结果和备份回收计划，再执行回收，避免中断留下无记录的备份。覆盖前原图发生变化时拒绝替换。启动不自动继续覆盖，用户从记录核对后才能恢复。原位覆盖完成的素材重新分配编号，避免复用旧预览及裁剪草稿；不支持原格式写回时先输出同目录 PNG，再核对并回收原件。

Live 移动的静态图和视频采用组级日志，所有成员确认后才允许该项离开本批。多文件操作不宣称原子性；部分完成时显示实际位置并提供恢复。

组级操作使用 `live_move` / `live_copy`，完整成员计划写入 `live_members` 后才开始变更文件。照片与视频共同避让目标重名，恢复逐成员核对身份和内容；任一成员缺失、被外部修改或原位置被占用时拒绝盲目恢复。操作记录按一张 Live 图展示，撤销恢复两个文件各自的原路径。跨盘移动保留两份来源直到全部目标校验成功，同盘部分移动保留实际结果供继续核对。

## 直接删除

批量和大图模式的底部垃圾桶按钮分别处理全部已选项和当前一项，无需目标目录或成功解码图片。确认弹窗冻结待处理列表，显示数量；批量筛选隐藏的选择仍在范围内，并单独提示。取消确认不执行文件操作。

直接删除以 `trash` 记录操作，复用 `recycle_members` 保存完整成员计划、内容与身份信息，不依赖裁剪输出。Live 图按完整资产回收，普通视频也支持回收。执行前校验文件版本及全部成员；成功项移出当前列表，失败项保留并提示，部分 Live 回收由日志记录实际结果。批量任务可停止未开始的项，已回收项不回滚。系统回收失败不改用永久删除，重启不会自动继续回收；恢复机制与下述裁剪后删除一致。

## 裁剪并删除原图

全部 PNG 输出成功后，将原文件成员及关联输出编号分别记录到 `recycle_members` 和 `recycle_outputs`，再执行回收。回收前锁定并重新核对子图 SHA-256，同时预检所有原文件的内容、身份、大小和修改时间。iPhone Live Photos 回收照片及配套视频；单文件实况图回收整个原文件，生成的子图均为普通静态图片。

使用 Windows 回收站，不提供永久删除兜底；失败保留子图并显示未完成记录。多文件回收不具有原子性：逐成员记账，部分成功时保留实际结果；原照片已不在原位置时从浏览列表移除，但未完成日志继续保留。用户可在操作记录中选择“核对并继续”，重新校验输出及剩余原文件后重试，已确认回收的成员不重复执行。

启动核对不会自动继续回收。若中断导致原文件缺失且日志未确认其回收结果，手动核对会结束该计划并停止其余回收，提示检查回收站和原目录，不推断为成功。恢复已回收文件请使用 Windows 回收站，操作记录不提供一键撤销回收。原文件恢复到当前来源范围内的原路径后，启动或刷新会解除其已处理标记并重新纳入浏览；这只更新列表，不重放回收或导出。

## 撤销与启动恢复

操作记录的时间在数据库中保持 UTC，界面转换为电脑本地时间并标注“本地时间”；转换包含日期，跨午夜不会显示为前一天。历史数据不改写。

操作记录提供“清空记录”，确认后从历史列表中永久清除所有已结束记录，不限于最近 100 项；这些记录不再提供界面撤销入口。清空不执行任何文件操作，不改变素材、草稿或智能学习记录。未完成操作及其关联父组继续显示并保留核对入口。底层操作编号、校验值与 Live 成员计划保留，用持久化的 `cleared_history` 标记隔离历史展示，避免破坏裁剪幂等重试或中断恢复；写入失败时事务回滚。新操作正常进入历史列表。

撤销前确认目标仍是原操作结果、内容未被外部改变、回退位置可用。原图移动可移回；子图输出只在确认未变时移入可恢复隔离区；目录撤销需核对子树与后续依赖，必要时按逆序处理。冲突时停止，不覆盖后续文件。

撤销旧批操作后提供返回原批或恢复队列，不悄悄插入正在多选的批次。编辑撤销与文件撤销分开，UI 提示将撤销的具体动作。

启动先检查未完成日志，核对来源、目标及临时文件，区分未开始、成功未记账、部分完成和冲突；不能无条件重放。对于处于 planned/running、未关联成组操作的移动或复制，只有系统确认目标和临时文件均不存在，且原文件身份、大小、修改时间与内容哈希完全一致时，才将该未生效记录标为已结束，允许重新操作。已有目标、临时文件、来源变化、无法读取及成组成员均保留待处理状态。此核对只更新日志，不执行文件转移。复制恢复只完成目标写入与校验，不删除来源；完整复制目标可以直接提交。已保存的草稿、范围和浏览位置可以恢复，未确认的导出不自动执行。

软件不自动归档原图；用户确认直接删除后回收所选文件；明确选择“裁剪并覆盖原图”或“裁剪并删除原图”时，在输出校验成功后回收原文件。用户外部删除、修改或磁盘损坏后，撤销能力取决于实际剩余文件，日志必须如实报告可恢复范围。

单文件临时提交可参考 [QSaveFile](https://doc.qt.io/qt-6/qsavefile.html)，它不能替代组级日志、跨盘校验或数据库对账。

## 目录重命名

支持目标根目录及内部普通子目录改名；磁盘或共享根路径不属于可改名的普通目录。拒绝非法名称、链接目录和同名覆盖。操作前记录来源、目标与 Windows 目录身份；文件系统改名成功后，以 SQLite 事务同步素材索引、来源、当前批次、待处理队列、裁剪草稿和文件操作记录中的路径。路径匹配以目录边界为准，不影响名称前缀相同的相邻目录。

若目录改名后中断，启动或操作记录核对时先验证目标目录身份，再补齐路径记录；身份不符时保留待核对记录。目录改名支持再次重命名，操作记录不提供一键撤销目录改名；此前文件移动的撤销使用更新后的路径。
